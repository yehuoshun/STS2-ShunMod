## 加新模板

### 什么时候加

- 第一次新建某个类型的文件（比如以后有了 Event 类文件）
- 现有模板不覆盖的常见类型

### 步骤

1. 在 `docs/templates/` 下新建 `New{类型}.cs.txt`
2. 从同类型已有代码中摘出完整结构作为模板底稿
3. 把可变部分换成占位符注释（参考现有模板风格）
4. 在文件顶部加检查清单，用 `[ ]` 格式
5. 在 `AGENTS.md` 的「改 X 看哪些文件」表格中加一行指向新模板
6. 在 `AGENTS.md` 的「使用指引 → 新文件模板」表格中加一行

### 模板规范

```
┌─────────────────────────────────────────────┐
│ // ─── 模板：{中文名} ─────────────────── │
│ // 用法：复制此文件，替换类名，填充逻辑。     │
│ // 检查清单（提交前逐项过）：                 │
│ //   [ ] 第一条                             │
│ //   [ ] 第二条                             │
│ //   [ ] git commit + push                  │
│                                              │
│ using ...                                    │
│ namespace ...;                               │
│                                              │
│ /// <summary>                                │
│ ///     {功能描述} — {一句话说明}。           │
│ /// </summary>                               │
│ ...实际代码，占位符用 {大括号} 标注...         │
└─────────────────────────────────────────────┘
```

**原则**：模板要完整到 Agent 能直接复制粘贴改，而不是还得猜结构。

## 改已有模板

### 什么时候改

- 游戏框架更新，API 签名变了（如 `CardModel` 构造函数）
- 踩坑后发现了更好的写法
- 编码约定调整

### 步骤

1. 直接改 `docs/templates/{文件名}`
2. 如果改动涉及 API 变化，在 `AGENTS.md` 的「已知坑点」加一条说明
3. 不需要改其他文件

### 注意事项

- 模板里的 `using` 要保持最小集，只引实际用到的命名空间
- 占位符注释要保持清晰，别让 Agent 看不懂该填什么
- 模板不包含业务逻辑，只包含框架结构

## 更新 AGENTS.md 踩坑日志

### 什么时候加新坑点

- Agent 被 CI 打回来，原因是文档没覆盖到的
- 发现了一个新的容易写错的地方
- 游戏框架行为变更

### 格式

每一条包含：问题现象 + 原因 + 解决方案。

```
6. **问题标题**：简单描述。当 X 时会出现 Y 错误。
7. **另一个坑**：原因是 Z。正确做法是 W。
```

### 什么时候删旧坑点

- 该坑点对应的游戏版本已过时
- 该问题已被模板或工具链自动规避（比如模板里写了正确的写法，就不需要再提醒了）

## 删模板

### 什么时候删

- 对应功能不再需要（比如某个模块被移除了）
- 模板内容严重过时且无法更新

### 步骤

1. 删 `docs/templates/{文件名}`
2. 删 `AGENTS.md` 中引用该模板的行
3. 如果该模板是某一类型文件的唯一模板，删掉 AGENTS.md 中对应类型的索引行

## 套用到其他项目

### 复制步骤

从 STS2-ShunMod 复制三件套到新项目：

```
AGENTS.md                  # 改内容，保留结构
docs/templates/            # 改模板内容，保留结构
docs/UPDATE.md             # 这个文件本身通用，不用改
```

### 需要改的内容

| 文件 | 改什么 |
|------|--------|
| `AGENTS.md` | 项目概要、技术栈、模块依赖、改 X 看哪些文件、已知坑点 |
| `docs/templates/*.cs.txt` | 命名空间、基类名、框架 API 名 |
| `docs/UPDATE.md` | 不需要改（通用指南） |

### 不需要改的内容

- `AGENTS.md` 的结构（项目概要 → 依赖 → 索引表 → 核心机制 → 编码约定 → 使用指引 → 坑点）
- 模板的格式（顶部注释块 → using → namespace → 占位符代码）
- `UPDATE.md` 全文

## 快速参考

| 需求 | 改哪里 | 关联改动 |
|------|--------|----------|
| 加新类型模板 | `docs/templates/New{类型}.cs.txt` | AGENTS.md 索引表 + 使用指引表格 |
| 改已有模板 | `docs/templates/{文件}` | 可能在 AGENTS.md 加坑点 |
| 记踩坑记录 | `AGENTS.md` 已知坑点 | 无 |
| 适配框架升级 | 模板 + AGENTS.md 坑点 | 无 |
| 套用到新项目 | 复制三件套，改内容 | 无 |
